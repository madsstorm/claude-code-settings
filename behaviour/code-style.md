## Code Style

### Code Readability

Write code that a developer can understand without needing to trace execution.

  - Use descriptive names — short or abbreviated names hide intent
  - Name new identifiers in English, even when surrounding code uses another language — leave existing names as they are
  - When in doubt, simplify — complex code hides bugs

### Comments

A comment should make sense to someone who only has the code.

  - Don't reference tickets, issues or work items in code comments — that link belongs in the commit message or pull request
  - If the reason behind the code matters, state it in the comment itself rather than pointing elsewhere
  - Keep comments short — a single line when reasonable; go longer only when the code can't be understood without it
